# Remote sensing estimates of negative air ion concentrations in Guangzhou parks

Code, source data, trained models and frozen validation outputs for the study *Temporal reconstruction and spatial transferability of remote sensing estimates of negative air ion concentrations in Guangzhou parks*.

This repository is the reproducibility package for the paper. It contains the station monitoring records, the Earth Engine exports used as predictors, the modelling table, the frozen model artifacts, all validation outputs that back the reported metrics, and the aggregated raster summaries. The manuscript, the supplementary file and the GeoTIFF layers themselves are **not** included here.

## Contents

| Directory | Contents |
|---|---|
| `data/` | Original monitoring records, six station-level GEE exports, modelling master table, fixed station groups, seven-park geometry. The original monitoring CSV uses GBK; other CSVs use UTF-8 or UTF-8 BOM. |
| `models/` | Frozen urban M4 production model and a separate archival reference bundle. |
| `results/validation/` | Formal M4 leave-one-station-out results, time-blocked predictions and the published model comparison. |
| `results/tables/` | The manuscript's Tables 1–4 and Supplementary Tables S1–S7 as CSV. |
| `results/raster/` | Aggregated raster summaries only (11 CSV/Markdown files); the GeoTIFF layers are archived separately. |
| `code/` | Preprocessing, model comparison, model export and raster processing. See [the code guide](code/README.md) for commands and dependencies. |

## Quick start

```bash
python -m pip install -r code/requirements.txt
python code/run.py check        # verifies the 5,998-row master and frozen metrics; does not train
python code/run.py validate     # refits the four models under the evaluation design
```

Raster workflows are **not** runnable out of the box. They need the archived GeoTIFF layers (masked NAI, seasonal/annual means and trend surfaces; about 254 MB, 336 files), which are kept out of Git:

```bash
# point at the raster archive, or restore it under results/raster/
export NAI_RASTER_DIR=/path/to/raster_archive      # Windows: set NAI_RASTER_DIR=...

python code/mapping/run_mapping.py clip
python code/mapping/run_mapping.py aggregate
python code/mapping/run_mapping.py trend
```

All new outputs are written outside this directory, by default to the sibling `NAI_reproduced/`.

## Raster archive

The GeoTIFF layers (336 files, about 254 MB) are not stored in Git. They are the masked NAI surfaces, seasonal and annual means, and the Theil–Sen/Mann–Kendall trend surfaces behind Figures 8–9. To restore the original layout, place the archive under `results/raster/`, or set `NAI_RASTER_DIR` to its location; `code/mapping/package_paths.py` reads that variable. The CSV and Markdown summaries retained in `results/raster/` document the aggregated values and do not require the layers.

## Known limitations

- Historical rasters are **exploratory model estimates**. They come from a seasonal-feature workflow that differs from aggregating daily station predictions; the station aggregation metrics do not establish pixel-level accuracy.
- Six archived park-amplitude rasters have a grid origin that differs from their seasonal source grids. Their arrays are retained in the raster archive as archived products; regenerate them with the aggregation command before spatial overlay. Annual-mean and trend rasters are unaffected, and the retained CSV summaries are not affected.
- The monitoring network has 14 stations, so daily and station-level results are limited by spatial sample size. See the manuscript discussion.

## Notes

- Historical maps use 36 three-month seasons grouped into nine March-to-February seasonal years, 2016–2024, covering March 2016–February 2025.
- Packaging checks did not refit models: they reproduced the master table byte-for-byte, checked the comparison assembly, loaded the production model for sample predictions and checked raster processing against frozen numerical outputs.
